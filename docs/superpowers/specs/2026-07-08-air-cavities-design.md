# Прослойки из HEAT 2 info log

## Цель

Добавить в приложение отдельную вкладку "Прослойки", которая читает HEAT 2 info log, извлекает размеры frame cavities и финальные значения `lambda`, а затем добавляет или обновляет соответствующие материалы в выбранном `.MTL` файле.

## Пользовательский поток

1. Пользователь вставляет текст HEAT 2 info log из буфера обмена. Текст лога не отображается в интерфейсе.
2. Пользователь выбирает существующий `.MTL` файл.
3. Пользователь задает базовое имя материала, выбирает общий цвет через кнопку-свотч и выбирает штриховку одной из семи кнопок.
4. Пользователь может включить добавление порядкового номера (`001`, `002`, `010`) и значения теплопроводности к имени материала.
5. Приложение показывает найденные прослойки и будущие имена материалов.
6. По кнопке "Добавить/обновить материалы" приложение записывает материалы в выбранный `.MTL`.

## Правила данных

- Используется последняя таблица `Cavity ... lambda ... Iter:*`, потому что она соответствует финальной итерации.
- Размеры берутся из последней таблицы `Cavity  b [mm]  d [mm]  area [mm²]`, доступной перед таблицей lambda.
- Номера `Cavity` в таблице размеров и таблице lambda должны совпадать.
- `thermal_x` и `thermal_y` создаваемого материала равны `lambda`.
- `volume_heat` задается как `0`.
- RGB берется из выбранного цвета, `special_value` берется из выбранной кнопки штриховки `0..6`.
- Если материал с таким сгенерированным именем уже есть в `.MTL`, запись обновляется. Если имени нет, запись добавляется в конец файла.

## Валидация

- Лог должен содержать таблицы размеров и lambda.
- Значения `b`, `d`, `area`, `lambda` должны быть положительными числами.
- Базовое имя не должно быть пустым, если выключены оба добавления к имени.
- Порядковый номер добавляется в формате из трех цифр.
- Теплопроводность добавляется как числовое значение без буквы `L`.
- Итоговое имя должно кодироваться в Windows-1251 и помещаться в 50 байт.
- RGB и специальное значение должны быть целыми числами в диапазоне `0..255`.
- Сгенерированные имена должны быть уникальны после нормализации.
- `.MTL` должен быть кратен размеру записи 89 байт и не содержать поврежденных записей при записи.

## Архитектура

- `src/air_cavities.py`: парсинг HEAT 2 info log, генерация `MTLMaterial`, обновление `.MTL`.
- `src/material_sort.py`: расширяется существующий MTL-парсер записью `.MTL` и полями `volume_heat`, RGB, `special_value`.
- `src/ui/air_cavities_page.py`: PyQt6-вкладка без отображения лога, с выбором `.MTL`, базовым именем, чекбоксами добавления номера/lambda, выбором цвета, кнопками штриховки и предпросмотром.
- `src/ui/main_window.py`: навигационная кнопка "Прослойки".

## Тесты

- Парсинг лога выбирает последнюю таблицу lambda.
- Ошибки лога и маски возвращаются как валидационные исключения.
- Обновление `.MTL` заменяет существующие записи и добавляет отсутствующие без дублей.
- Главное окно содержит новую вкладку.
